# Теория и защита

## Что демонстрирует проект

`Modifier` — неизменяемая упорядоченная цепочка оформления, измерения, размещения и поведения Compose-компонента. Пустой `Modifier` не добавляет действий. Методы возвращают новую цепочку; исходную можно переиспользовать.

Порядок принципиален: `border().padding()` рисует рамку вокруг внутреннего отступа, а `padding().border()` оставляет отступ снаружи рамки. `then(other)` присоединяет цепочку, а не сортирует, не отменяет предыдущие операции и не является отдельным ключевым словом Kotlin.

В final DemoScreen `border(2.dp).padding(10.dp).then(height(100.dp))` задаёт высоту внутренней области текста, после чего внешний размер включает padding. `Scaffold` передаёт `innerPadding`; корневой Column принимает его один раз, иначе содержимое может перекрываться системными панелями или получить двойной отступ.

Собственный composable принимает `modifier: Modifier = Modifier` первым необязательным параметром после обязательных. Принятый modifier должен попасть на корень ровно один раз. В `CustomImage` обязательный аргумент `image` остаётся первым; дополнительный `contentDescription` идёт после modifier, имеет null по умолчанию, но для фотографии в основном экране передано осмысленное описание.

`dp` — логические единицы, зависящие от плотности экрана; `sp` дополнительно учитывает пользовательский масштаб текста. `width(270.dp)` работает в пределах constraints родителя, это не гарантия ширины на произвольно узком экране. `clip(RoundedCornerShape(30.dp))` обрезает содержимое до формы, а не меняет сам JPEG.

## Частые модификаторы из раздела 6 лекции

- `background`, `border` — фон и рамка; `clip` — обрезка содержимого.
- `padding` — пространство вокруг содержимого; `offset` — смещение размещения.
- `size`, `width`, `height` — желаемые размеры с учётом constraints.
- `fillMaxWidth`, `fillMaxHeight`, `fillMaxSize` — заполнение разрешённого родителем размера.
- `clickable` — обработка нажатия и стандартная обратная связь.
- `rotate`, `scale` — визуальные преобразования.
- `layout` — пользовательские измерение и размещение.
- `scrollable` — обработка жестов/дельт прокрутки; само по себе это не готовое перемещение контента. Для простого прокручиваемого Column обычно используют `verticalScroll`.

Этот раздел лекции перечисляет API, но не требует добавлять в приложение все эти операции. Реализованы все её пошаговые изменения, а не искусственная галерея несвязанных эффектов.

## Уточнения исходной методички

- Имя параметра в Kotlin — `modifier`, тип — `Modifier`: слово с прописной буквой в пояснении лекции является неточностью.
- Исходный ресурс называется `vacation.jpg`, хотя рядом в тексте встречается `vacation.png`.
- В объяснениях размеры названы пикселями, но в коде используются dp/sp.
- Пример с Column отдаёт входной modifier только Text; в проекте он передан корневому Column, чтобы соблюсти контракт внешнего modifier и сохранить insets.
- В ранних этапах 02–05 входной modifier уже сохраняется; отдельный этап 06 показывает переход к построению основной цепочки непосредственно от него.
- Доступное описание фотографии добавлено только дополнительным этапом 17. Исторические APK 09–16 сохраняют декоративный `contentDescription = null` из лекции.

## Семь вопросов для защиты

1. **Зачем нужен Modifier?** Чтобы последовательно настраивать размер, отступы, рисование, размещение и поведение компонента.
2. **Почему border и padding нельзя бездумно менять местами?** Внешняя операция оборачивает внутреннюю: меняется положение рамки относительно отступа.
3. **Что означает `Modifier = Modifier`?** Параметр типа Modifier по умолчанию содержит пустую цепочку, поэтому его можно не передавать.
4. **Зачем передавать modifier корневому Image?** Иначе вызывающая сторона не сможет управлять размером и оформлением собственного компонента.
5. **Чем dp отличается от sp?** dp учитывает плотность, sp также масштабирование шрифта.
6. **Что делает then?** Последовательно соединяет цепочки; порядок элементов сохраняется.
7. **Что такое detached HEAD и как вернуться?** HEAD указывает прямо на коммит, а не ветку; после просмотра нужно переключиться на сохранённое имя ветки и сверить прежний HEAD, не теряя незакоммиченные изменения.
