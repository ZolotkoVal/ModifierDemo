## Проверка инструментальной цепочки

Обычная задача `connectedDebugAndroidTest` первоначально упала **до выполнения тестов**: `ClassNotFoundException: worker.org.gradle.process.internal.worker.GradleWorkerMain`. Неуспешные логи сохранены, не заменены успешными результатами adb.

Диагностика установила несовместимость чтения UTF-8 Java `@argfile` с кириллицей в пути Gradle home и кодировкой Windows ACP 1251. Jar исправен; прямой Unicode classpath и копия argfile в CP1251 загружают класс. На независимой копии Gradle home в ASCII-каталоге проверен полноценный `WorkerExecutor.processIsolation`: `LAB_WORKER_OK`, exit 0 в обоих проектах. Глобальные настройки Windows, Java и Gradle не менялись.

Воспроизводимый обход хранится вне репозитория: `resume/run_connected_ascii.py`, диагностика — `resume/GRADLE_WORKER_DIAGNOSIS.md`. Для обычной среды можно пользоваться wrapper; на этой машине при той же ошибке можно использовать отдельный ASCII Gradle home в окружении дочернего процесса. Connected-прогон через этот обход не выполнялся: по просьбе пользователя уже успешные пять Android-тестов ModifierDemo повторно не запускались. Подтверждённый результат — прямой AndroidJUnitRunner, не Gradle connected.
